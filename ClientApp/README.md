# MpsClient

Angular 21 client for MPS (Multiplayer Shopping List). Originally generated with Angular CLI 14.0.2.

Traditional NgModule app (not standalone), built with the esbuild-based `@angular/build:application`
builder. See `../CLAUDE.md` for architecture and conventions.

## Development server

Run `npm start` for a dev server on <https://localhost:44443>. It serves over HTTPS using the
ASP.NET dev certificate (generated by the `prestart` hook, `aspnetcore-https.js`) and proxies `/api`,
`/live`, `/Account` and `/signin-microsoft` to the backend via `proxy.conf.js`. `ng serve` on its own
will not work — the port, certificate and proxy all come from the npm script.

A backend path missing from the `proxy.conf.js` context list falls through to the SPA and shows up as
an Angular "cannot match any routes" error.

## Code scaffolding

Run `ng generate component component-name`. `skipTests: true` is set in the schematics, so no spec
files are created. New components need declaring in `AppModule`.

## Build

- `npm run build` — development build
- `npm run publish` — production build, consumed by `../publish.sh` and the Dockerfiles

Artifacts land flat in `dist/` rather than the Angular default `dist/browser/`, because the
Dockerfiles copy `ClientApp/dist/` straight into `wwwroot`. This is configured via `outputPath` in
`angular.json`.

## Tests

There are none. `angular.json` has no `test` target, so `npm test` fails. Angular 21's default test
runner is Vitest if any are added later.
